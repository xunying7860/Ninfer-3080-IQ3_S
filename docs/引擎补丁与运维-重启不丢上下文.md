# 引擎补丁与运维：让「重启不丢上下文」真正生效（2026-10-10）

本文件记录我们对 **NInfer 引擎本体**做的补丁、以及配套的构建 / 判据 / 回滚流程。
所有结论都有实机判据（x99：Ubuntu 22.04 + RTX 3080 20GB 单卡，IQ3_S 制品，sm_86）。

## 1. 现象与判据

| 场景 | 修前 | 修后 |
|---|---|---|
| **单会话**跑完 → 直接 `systemctl restart ninfer` → 回同一题面 | 27–28 s（整段重算） | **1.2 s**（从磁盘层恢复） |
| 被另外两个会话「挤出」的会话 → 重启 → 回同一题面 | 0.6–1.2 s ✓ | 同 ✓ |

判据工具见 `scripts/`（第 7 节）。

## 2. 根因链（逐层实测，每层都有诊断行）

1. 磁盘层（`--disk-kv-path` / `--disk-kv-gib` / `--disk-kv-restore`）只落 **`ContinuationSlotRole::Catalogued`** 的续段，
   且原有实现只在**释放 / 挤出**路径上写 ⇒ **单会话从不被挤出 ⇒ 永不落盘**。
2. 退役路径 `retire_continuation_slot()`（`src/models/qwen3_5/program/storage/context.cpp`）先把
   `text_kv_valid=0`、`endpoint_valid=false` 清零、再释放 KV；而 `plan_owner_spill()` 的 **StateImage 项要求
   `endpoint_valid == true`** ⇒ 之后任何落盘都只剩 KV 页（诊断 `spill plan items=2`），磁盘上
   `live_state_frontiers()` 为空 ⇒ 恢复侧枚举不到候选。
3. 在 `release_active_sequence_kv_strict()` 里补落盘同样无效 —— 诊断打的是 **`kv=0`**：
   `unbind_sequence_kv(state)` 更早把 KV 摘掉了。
4. **唯一正确落盘点**：`transactions/commit.cpp` 请求提交成功、KV 仍绑在 `state` 上、
   且在 `unbind_sequence_kv(state)` **之前**：

   ```cpp
   if (disk_kv) { spill_released_owner(state); }
   ```

   已写过的页由 `disk_kv->contains` 跳过 ⇒ 每轮只写增量（实测首次 `items=1130` = 整段迁移）。

## 3. 顺带修掉的两个上游 bug（否则根本编不出可用件）

- **`src/ops/CMakeLists.txt` 次序笔误**：`nvfp4_sm86_stubs.cpp` 被加在
  `set_property(TARGET ninfer_ops PROPERTY SOURCES ...)` **之前** ⇒ 被整体覆盖 ⇒ sm_86 链接期
  `undefined reference: nvfp4_*_w4a4_launch / launch_nvfp4_w4a4_quantize / nvfp4_linear_swiglu_w4a4_tma`。
  修法：把该 `target_sources` 挪到 `set_property` **之后**（与本来就正确的 fp8 桩写法一致）。
- **仓内 `Dockerfile` 给 CUDA 挂了 ccache**（`-DCMAKE_CUDA_COMPILER_LAUNCHER=ccache`）⇒ nvcc 13.3 必坏。
  修法：删掉该行，C/CXX 的缓存保留。

## 4. 从零重建

- 源码：codeload `iamwavecut/ninfer-all` @ **60f18c3**（厂商 `README.txt` 指名的引擎出处；本机仅 codeload 通道可用）。
- 构建：`docker build --progress=plain -f <树>/Dockerfile <树>`；基座 `nvidia/cuda:13.1.2-devel-ubuntu24.04`；
  `CMakeLists.txt` 默认已是 `CMAKE_CUDA_ARCHITECTURES=86`。产物在镜像 **`/usr/local/bin/ninfer-serve`**。
- **改 `.cpp` = 增量编译（≈3 分钟）**；改 cmake 文件才会换构建目录、全量重编（≈36 分钟）。
- 一键流水线：`scripts/diag-spill-pipeline.sh`
  （加诊断 → 构建 → 取件 → 备份+换件+重启 → **单会话直接重启**判据 → **仅失败自动回滚**）。

## 5. 回退

```bash
cp /data/ninfer/bundle/bin/ninfer-serve.bak-*-diag /data/ninfer/bundle/bin/ninfer-serve
sudo systemctl restart ninfer
```

（备份即厂商原件，1,249,869,248 B）

## 6. 注意事项

- 生产现跑的是**自编补丁件**，与厂商原件不再逐字节一致 ⇒ **以后更新 ninfer 必须从这棵树重编**。
- 配套参数：`--disk-kv-path /data/nvme/ninfer-disktier --disk-kv-gib 64 --disk-kv-restore`
  ＋ `--max-private-continuations 1`（第二层保障：被挤出的会话重启 0.6 s 恢复）。
- 磁盘层文件是**稀疏预分配**（名义 64 G，`du` 看到的才是真占用；实测约 13 G 起随会话增长，超预算 LRU 淘汰）。
- 面板口径：`tg` 取引擎日志 `throughput` 行的 decode 速率（需 `--log-stats-interval-ms 1000`），
  `tg_3s` 为其 3 秒窗均值 —— 两者必须分家，否则说明统计行间隔还是 5 秒。

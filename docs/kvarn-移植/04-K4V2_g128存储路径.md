## 4.2 beellama 的模型：已完成组与未完成组是两条路

[`llama-kv-cache-kvarn.h:47`](https://github.com/Anbeeld/beellama.cpp/blob/main/src/llama-kv-cache-kvarn.h#L47) 原文：

```c
// Completed groups are committed eagerly. Only the currently incomplete group
// needs persistent quantization workspace, regardless of physical ubatch size.
inline uint32_t llama_kvarn_workspace_groups(uint32_t n_ubatch) {
    GGML_UNUSED(n_ubatch);
    return 1;
}
```

以及 [`:51`](https://github.com/Anbeeld/beellama.cpp/blob/main/src/llama-kv-cache-kvarn.h#L51) 的注释：

> Reference KVarN keeps only the currently incomplete 128-token group in F16, and **completed groups are quantized before the next group starts**.

beellama 的 store kernel 分三类，从 route stats 结构（[`kvarn.cuh:7`](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cuh#L7)）可读出：

| 字段 | 含义 |
|---|---|
| `direct_store` | 直接整组写 record |
| `single_slice_workspace` | 单 slice 走 workspace |
| `headwide_workspace` / `headwide_monolithic` | 跨 head 合并 |
| `high_shared_fallback` / `low_shared_store` | smem 不足回退 |
| `sealer_128` / `sealer_256` / `sealer_candidates` | **封口器**（把攒满的组量化落盘） |

**`sealer` 就是你要的第三条路**：平时写 F16 stage，攒满一个 group 时由 sealer 量化落 record。

## 4.3 三路拆分（建议实现）

按「本次写入后本组的填充状态」分派，**B 路径不碰 metadata**：

| 路径 | 触发条件 | 动作 | 需要 block-table |
|---|---|---|---|
| **A · 整组直写** | 起始对齐且本次写满 128 | 直接量化写 record | **需要** |
| **B · 组中间** | 本组未攒满 | 写 F16 stage，**不编码** | **不需要** |
| **C · 封口** | 本组刚攒满（由 B 累积触发） | 从 stage 取全组 → 量化写 record | **需要** |

```cpp
// 伪码
constexpr uint32_t GROUP = 128;
uint32_t base = pos0 / GROUP * GROUP;   // 本组起始
uint32_t off  = pos0 - base;            // 组内已写量
uint32_t n    = tokens;

if (off == 0 && n == GROUP) {
    launch_encode_direct(...);          // A：需要 metadata
} else if (off + n < GROUP) {
    launch_stage_only(...);             // B：不需要 metadata
} else {
    launch_seal_from_stage(..., GROUP - off);   // C：需要 metadata
    // 剩余部分递归
}
```

你的 `tokens=51`、`columns=51` 应落在 **B**（若 off=0）。

## 4.4 stage slot 分配（照抄 beellama）

[`kvarn.cu:759`](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cu#L759) 原文：

```c
const int stage_slot = assigned_slot >= 0 ? assigned_slot :
    (swa ? (stage_group % stage_groups) : (1 + ((stage_group - 1) % tail_groups)));
```

非 SWA、`tail_groups = 2` → slot 在 **{1, 2}** ping-pong。

索引编码用 beellama 的 int64 打包（[`llama-kvarn.h:16`](https://github.com/Anbeeld/beellama.cpp/blob/main/src/llama-kvarn.h#L16)）：

```c
constexpr int64_t llama_kvarn_encode_store_cell(uint32_t cell, uint32_t stage_slot) {
    return int64_t((uint64_t(stage_slot) + 1u) << 32u | uint64_t(cell));
}
constexpr int64_t llama_kvarn_encode_stage_cell(uint32_t cell) {
    return -int64_t(cell) - 2;
}
```

**slot 是 1-based，0 保留给"无显式槽"**；负数编码区分 stage 与 store。直接照搬，边界情况 beellama 已处理。

## 4.5 两个 slot 的必要性（你的 MTP 场景）

`non_swa_tail_groups = 2` 的理由（源码注释）：

> `llama_kvarn_can_remove_range` promises a position-independent suffix rollback that reaches back into **the previous group** … With a single slot both groups alias one stage row range, so **re-sealing a partially reopened group sources its surviving prefix from the newer group's rows**.

**你的 `--spec mtp` 被拒 draft 回滚正好走这条。** 单 slot 会产生静默错误（不报错、内容错）。

beellama 实测深度 1/2 困惑度完全相同（7.1898），所以**第二个 slot 是纯正确性保险，不是性能冗余**。

预算：2 slot × 128 token × 4 head × 256 dim × K/V × 2 B ≈ **1 MiB/层**（全注意力层）。

## 4.6 ninfer 侧接线点

| 位置 | 改动 |
|---|---|
| `src/core/paged_kv_cache.cpp` | 1 tile = **2 pages**（64×2），页成对分配，tile 起始页必须偶数 |
| `src/ops/kernel/`（**注意：`paged_kv_window.cuh` 在 pin `60f18c3` 不存在**）或 `src/ops/kv_cache/append/*` | 同 tile 的 128 token 共享一条 record 头；须重新定位窗口内核落点 |
| `src/ops/kernel/paged_kv_address.cuh` | **A/C 用 `table_rows` 定位，不要用 `valid_columns`**（Masked=false 时它是 nil） |
| prefix cache | 对齐到 128（tile）而非 64（page） |
| `--kv-capacity` | 取整到 128 倍数；327,680 / 128 = **2,560 tiles ✓** |
| `--prefill-chunk 1024` | 1024 / 128 = **8 tiles ✓ 整数倍** |

**冒烟建议**：加一次 `--prefill-chunk 1000`（**非 128 倍数**）——整数倍路径会让跨组与尾块逻辑测不到。

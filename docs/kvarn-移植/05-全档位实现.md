# 05 · 全档位实现（2/3/4/5/6/8-bit）

---

## 5.1 位串打包是唯一能覆盖全部档位的实现

`bits` 合法值（[`kvarn.cu:447`](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cu#L447)）：

```c
static bool ggml_cuda_kvarn_valid_bits(int bits) {
    return bits == 2 || bits == 3 || bits == 4 || bits == 5 || bits == 6 || bits == 8;
}
```

**3/5/6-bit 不是字节的整数分之一**（8/3、8/5、8/6 都非整），nibble 打包完全失效。必须走位串：

```c
// src/llama-kvarn.cpp:715（CPU 真值）
void llama_kvarn_pack_bits(const uint8_t * values, int n_values, int bits, uint8_t * dst) {
    std::memset(dst, 0, llama_kvarn_packed_bytes(n_values, bits));   // 必须清零
    const uint8_t mask = (1u << bits) - 1u;
    for (int i = 0; i < n_values; ++i) {
        const uint8_t value = values[i] & mask;
        const size_t bit_offset = size_t(i) * size_t(bits);
        for (int bit = 0; bit < bits; ++bit) {
            const size_t dst_bit = bit_offset + size_t(bit);
            dst[dst_bit / 8] |= ((value >> bit) & 1u) << (dst_bit % 8);
        }
    }
}
```

位序：**第 i 值的第 bit 位 → 全局位 `i*bits + bit`**，小端。GPU 侧 `kvarn_quantize_tile` 里的写法与之一致（见 `03` §3.6）。

### GPU 侧实现策略

| 位宽 | 建议 |
|---|---|
| **2 / 4 / 8** | 可用向量化快路径（整字节/整 nibble 对齐），先保证与位串一致 |
| **3 / 5 / 6** | 必须逐 bit 通用路径 |
| 统一方案 | **先全部走位串通用路径**（正确性优先），性能后优化 |

**注意**：`row_bytes = 128 * bits / 8`，3-bit 时 = 48 B（整数 ✓，因为 128×3=384 bit = 48 B）。但**单个值会跨字节边界**，所以 memset 清零 + `|=` 是必需的，不能按字节赋值。

## 5.4 档位注册与 CLI

### 命名（对齐 beellama 的 `kvarnN`，但明确 K/V）

beellama 是 `-ctk kvarn4 -ctv kvarn2` 两个独立参数。ninfer 单参数更省事，建议：

```
--kv-dtype kvarn            → K4V4（默认档，**主档**，对标 rk4v4）
--kv-dtype kvarn-k4v2       → K4V2  ← 对照臂（已判死）
--kv-dtype kvarn-k2v4 / kvarn-k3v3 / ...
```

或拆两个参数（更接近 beellama、更易扩展）：

```
--kvarn-k-bits 4 --kvarn-v-bits 2
```

**推荐后者**——36 组合不需要 36 个枚举值。

## 5.5 位宽是运行期还是编译期

beellama 全运行期（op_params[0]）。建议 ninfer 侧：

- **布局计算**：运行期（tile 字节数随 bits 变）
- **kernel 分派**：`bits` 走 `switch` 分派到模板实例，2/4/8 用快路径、3/5/6 用通用位串

编译期模板会导致 36 个实例爆炸，只实例化**实际会用的档位**（建议先 K4V2 / K4V4 / K4V3 / K3V4 四个）。

## 5.6 decode 侧（全档位通用）

beellama 的 `materialize` 路径（[`kvarn.cu:2780`](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cu#L2780) / [`:3088`](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cu#L3088)）把 record 解回 F16 再算 attention。

**ninfer 不该照抄**——ninfer 的 rk8v4 本来就在量化域做 QK。KVarN 的 scale 是 rank-1 外积，可拆：

```
K 侧： k[d,g] = (qc[d,g]·s_col[d] + zp[d]) · s_row[g]
       logit[g] = s_row[g] · ( Σ_d (q[d]·s_col[d])·qc[d,g] + Σ_d q[d]·zp[d] )
V 侧： v[g,d] = (vc[g,d]·s_row[g] + zp[g]) · s_col[d]
       out[d]  = s_col_V[d] · ( Σ_g (p[g]·s_row_V[g])·vc[g,d] + Σ_g p[g]·zp_V[g] )
```

即 `s_col` 预乘到 Q、`s_row` 预乘到 softmax 权重，`zp` 退化为每 head 一个标量。

**但这是 ninfer 的既有优化，与 beellama 的 materialize 数值未必 bit-exact。** 建议：

1. **先按 beellama 的 materialize 路径做一遍**（保证与上游 bit-exact，用于验证 codec）；
2. 验证通过后再切量化域快路径；
3. 两条路径都应保留，用环境变量切换，便于回归对比。

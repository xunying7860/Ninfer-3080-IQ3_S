## 4. dump 格式与最小例子

完整规范见 `verify-g128/README.md` §3。要点：

**KVD1（引擎 plane dump；`code` 段 + `scale` 段 + 页数/token 数）** 全部小端、无 padding：

```
u32 'KVD1'(0x3144564B) | u32 ver=1 | u32 n_records
每条: u32 name_len; u8 name[]; i32 kind; i32 bits; i32 rows; i32 cols; i32 tokens;
      i32 pages; i32 head_slices; u32 flags(bit0=带原值);
      u32 code_bytes; u8 code[code_bytes];                       ← 「一段 record 字节」
      u32 scale_halfs; u16 scale[scale_halfs];                    ← 「一段 scale 字节」
      [flags&1] u32 orig_floats; f32 orig[orig_floats]
scale 段语义: [0,rows)=scale_axis(已折行因子) | [rows,2rows)=zp_axis(已折行因子) | [2rows,+cols)=other_axis(列因子)
相邻两条 record = 同一 head 的 slice0/slice1
```

**最小例子（实测产物 `data/fake_min.dump`，298,224 B = 12 + 4×74,553）**：

```
0000000 4b 56 44 31 01 00 00 00 04 00 00 00     'KVD1' ver=1 n_records=4
第一条 record（偏移 12）：
  12: 09 00 00 00                  name_len=9
  16: 66 61 6b 65 5f 4b 5f 73 30   "fake_K_s0"
  25: 00 00 00 00   kind=0(K)      29: 04 00 00 00   bits=4
  33: 80 00 00 00   rows=128       37: 80 00 00 00   cols=128
  41: 80 00 00 00   tokens=128     45: 02 00 00 00   pages=2
  49: 02 00 00 00   head_slices=2  53: 01 00 00 00   flags=1(带原值)
  57: 00 20 00 00   code_bytes=8192
  61: <8192 B 码> <768 B = 384×fp16 scale> <4 B> <65536 B = 16384×f32 原值>
```

**KVO1（引擎解码输出，`--decoded`）**：`u32 'KVO1' | u32 ver=1 | u32 n_heads`；
每 head `u32 name_len; u8 name[]; i32 kind; i32 tokens; i32 width(256); i32 domain(0=旋转域,1=已逆旋转); u32 n_floats; f32 data[tokens*256]`（`data[t*256+d]`，d = s*128+dl）。

CH1 侧写 dump 的最短 C 片段、以及「只喂 plane 字节（flags=0）时的退化行为」都写在 README §3.2。

## 5. 过 / 不过的判据（原文）

**算过**：

- **判据 A（`record 解码 == 主机反量化`）**：有 `--decoded` 时 —— 每个 head 的
  `cos(引擎解码输出, 主机反量化) ≥ 0.999`；无 `--decoded` 时 —— 两条独立解码路径逐元素 `maxabs == 0`（工具自洽见证）。
- **判据 B**：`nonfinite == 0`。
- **A ∧ B ⇒ PASS**。

**不过 ⇒ 病灶在哪**：

| 现象 | 结论 |
|---|---|
| `cos(引擎解码输出, 主机反量化) < 0.999`，而 `cos_adq_orig` 正常 | **解码端**：列因子/行 scale 折叠乘重或漏乘、位序/半字节槽位寻址错、`domain` 与逆旋转不匹配 |
| `cos_adq_orig < 0.99`（`bits ≥ 4`） | **编码端**：量化 kernel / 旋转 / F16 stage |
| 两条都对，但 `cos(引擎解码输出, 原值)` 崩 | 引擎解出来的值没喂到 attention，或喂前又被动过 |
| `nonfinite > 0` | 读到未初始化/padding 页或错 plane（`scale_leading_extent` 给错） |

`bits=2` 的 `cos_adq_orig ≈ 0.90` 是量化噪声本身、**不计入判据**（阶段 0 已定 K4V2 不上线）。

## 6. 边界（必须一起交出去，别让工具被过度信任）

1. **没有 `--decoded` 时判据 A 只是自洽见证**：两条路径读同一份字节、数学等价，必然 1.0。
   判**引擎实现**必须让引擎 dump KVO1。
2. **`--from-dump` 假定 plane 字节 == beellama record 布局**（`payload || scale_axis || zp_axis || other_axis`）。
   若引擎用 P1 的「页自足 + 槽位」布局（接线细案 §2.3：每页 64 token、维轴按页存两份），
   dump 前要按 record 语义重排，或扩展 reader —— 这一步**没做**，是 CH1 接线时的接口约定。
3. 逆旋转用 `norm_hadamard_256`（整数 FWHT + 精确 `2^-4`）。若引擎实际用 beellama 的
   `0.08838834764831845f × 0.7071067811865475f = 0.062499997860716139`（与 1/16 差 0.57 ulp），
   cosine 仍 ≥ 0.999 但**逐字节不会相等** —— 别拿这条当逐字节判据（与 `两道gate结论` §gate1 一致）。
4. 未与引擎真跑对拍过（引擎尚未跑起来，CH1 在做）；工具侧只对本机 oracle 与自造数据负责。

## 7. 卡点 / 没做的事

- 无实质卡点。工具、格式、判据、自证全部真跑出来。
- **没做**：真引擎 plane 的 KVD1 转换器（引擎里没有 dump 代码，且 P1 槽位重排的口径未定，见 §6.2）。
- 容器内 `nvidia/cuda:13.1.2-devel-ubuntu24.04` 无 `python3`，故假 dump 生成默认走 C++ `--gen-fake`；
  python 版（`tools/make_fake_dump.py`）在宿主上跑，已作为独立第二实现验证过。

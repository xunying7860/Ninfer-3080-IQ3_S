## 10. 建议

1. 门禁的 `ctrl vs rst` FAIL 是新件相对生产件的**真回归信号**（同件重启不复现、生产件复现稳定），优先按 §9 第一行的消融顺序查，别先动 KVarN 侧代码。
2. 若消融指向上游（②③④），处理方式是**给新件补一个"与生产同思考档 + 关 ngram"的启动口径**（写进启动脚本固化），而不是回退我们的接线——我们的接线只加 KVarN 分支，`rk4v4` 路径在短确定题上逐字同。
3. 严格单变量对照需要生产件版本确定（§9 第二行），否则 A/B 永远差着上游与 profile 两个变量。
4. 修 ngram 复制起草写 KV 的那条路（判据 = `gate_test.py` 的 `ctrl/rst/rst2` 三套件，GATE_DOC_LINES 1200、`GATE_NONCE=gate-prod`）；修完再谈新件顶替生产件。
5. `--ngram-draft-tokens 0` 只当定位手段；用它当生产规避要先复现 §11.3 那个 `public token domain` FATAL（全仓 1 次，尚未复现）。

## 11. 归因消融（2026-10-14 10:1x–11:2x，x99；子代理跑、我本地复核）

### 11.1 四病因判定

| 病因 | 判定 | 决定性证据（原始行/数字） |
|---|---|---|
| ② ngram 混合投机 | **成立** | `gatelogs/CUR-NG-r1-cmp-ctrl-rst.log` 与 `…-rst-rst2.log` 均 `### VERDICT: PASS(逐 token 一致)`；同轮 R2 从 `mixed speculation accepted 19/24 (79.2%) | ngram 10/15 accepted, 1 rounds` 变 `mtp accepted 18/18 (100.0%)` |
| ① 我们的接线 | **出局** | 归档件 PRE md5 `b2a72ecc73a54eef2b1eaeec28226d70`、build 行 `0.12.0-rtx3090+034347f-dirty`；PRE r1/r2 与 CUR r1/r2 **各 2 轮 ctrl/rst2 全 FAIL 且 R4 原文逐字同**；**PRE vs CUR 前 200 字 22/22、全文逐字 22/22** |
| ③ profile 重标定/路由 | **出局（仅对门禁）** | `--ngram-draft-tokens 0` 档仍读同一份 v2 profile（三份副本 md5 全 `7277b862f5c7319fc534c50bbc57a436`，起前起后未变、无重标定），门禁即 PASS |
| ④ 思考档/chat template 处理 | **差异属实，中和不了，且与门禁无关** | A/PRE 22/22 `thinking template default` vs B 22/22 `thinking xhigh`；`--default-reasoning-effort xhigh` 后日志仍 `thinking template default`；payload 试 5 种（`reasoning_effort=xhigh`、`chat_template_kwargs{enable_thinking:true,…}` 等）`reasoning_tokens` **恒 109**（B=430），`prompt_tokens` 两臂同为 107 ⇒ 日志字段只是请求值回显；该档门禁仍 FAIL（门禁两臂 `thinking off`） |

### 11.2 机制：不是随机，是 ngram 复制起草写的 KV 与冷算不等价

`R2 是否吃到前缀缓存` 决定 `R4 那句有没有「为」`。我把全部 30 组（10 臂 × ctrl/rst/rst2）逐条拉回本地重算：**符合 28/30，两处例外正好是唯二 PASS 的两臂**（B-rst 与 CUR-NG-r1-rst，都是 `cache 0.0` 却仍写「为」）：

| 臂 | ctrl（R2 cache 99.9%） | rst（R2 cache 0.0%） | rst2（99.9%） |
|---|---|---|---|
| A、A2、PRE-r1、PRE-r2、CUR-r1、CUR-r2、CUR-NGT、CUR-XH | `暗号为…` | `暗号…`（丢「为」） | `暗号为…` |
| B、CUR-NG（ngram 关） | `暗号为…` | `暗号为…` | `暗号为…` |

⇒ 病灶 = `ngram` 复制起草那条路写进 KV 的内容与冷算不等价（缓存命中时用它写的 KV，冷算时不用），不是缓存坏、不是路由、不是我们的接线。

### 11.3 消融开关与副作用

`--help` 原文（存 `/data/kvarn/g128-rk4v4-test/ev/CUR-help.txt`）：

```
--ngram-draft-tokens N   copy up to N tokens (1..63) per round from
                         earlier prompt, tool-result or output text,
                         verified alongside --spec; on with 15 whenever
                         --spec is set, 0 disables it, above 15 needs
                         --max-concurrency 1
--no-ngram-table         Qwen3.8-Flash-Next: run without the n-gram table.
```

- `--no-ngram-table` 无效（该开关只管 Qwen3.8-Flash-Next，本模型不是）：日志仍 `ngram 10/15 accepted`，门禁仍 FAIL/FAIL。

| PRE（接线中途快照） | 13/22 = 59.1%，分歧位置与 CUR 逐条相同 | 我们的接线对这条分歧**贡献 0** |
| CUR-NG（关 ngram） | 2/7（长答子集） | 长度变了（Q1 1814→1832、Q2 1715→1699）⇒ ② 有影响，但分歧不消失 |
| CUR-NG-effXH（关 ngram + 思考档对齐） | 2/8 | 同上，仍与 B 不一致 |

⇒ 分歧属**新件基线（`11327e96` 系）相对生产件的漂移**（ngram、思考档/模板处理、v2 路由三项都在漂移里），要再切细需要一个只差 v1/v2 路由或只差 KVarN 的对照件，现树里没有。

### 11.5 这条结论对 KVarN 线的意义

**我们的接线在 `rk4v4` 上是零影响**（PRE vs CUR 全文逐字 22/22），所以「同二进制换 `KV_DTYPE`」的 A/B 对照臂成立，KVarN 的质量结论不受本次漂移影响。但它说明：**要把新件顶替生产件，得先解决 ngram 起草写 KV 的等价性**（否则门禁 `ctrl/rst/rst2` 不过），而 `--ngram-draft-tokens 0` 自己另有一个引擎级 FATAL，不能直接当规避手段。

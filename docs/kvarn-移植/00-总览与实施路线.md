版本：2026-10-13。重点档位 **K4V4_g128**（阶段 0 实测：K4V2_g128 超判据 25–29 倍判死；K4V4_g128 与生产打平），K4V2 降为对照臂；同时完整支持 K/V 独立 2/3/4/5/6/8-bit。

## 二、四条必须纠正的前置认知

这四条会直接改变你的实现方式，先接受再开工。

### 1. smem 够用，不需要"原地缩放"那套

我此前给的方案建议过"单缓冲原地更新 + 收尾反推 best"，那是**过度设计**。

beellama 实测：`KVAR_N_SHARED_FLOATS = 16384 + 8×128 + 2 + 16 = 17,426` → **68.1 KB**，而 sm_86 的 `smpbo`（per-block opt-in shared）约 **99 KB**。**直接装得下，余 30.9 KB。**

正确做法（beellama 原文）：**tile 常驻 smem 且从不修改**，每次迭代用当前 scale 重新除原始值：

```c
// kvarn.cu:554 —— 每次都从原始 tile 重算，不是原地缩放
const float value = tile[row * 128 + col] / (sc * s_row[row]);
```

这比原地累积更安全（无误差累积），也更好对照。

### 2. 量化是 **per-row RTN**，不是 per-tile

这是最容易搞错的一点。beellama 在 `kvarn_quantize_tile`（[kvarn.cu:660](https://github.com/Anbeeld/beellama.cpp/blob/main/ggml/src/ggml-cuda/kvarn.cu#L660)）里：

```c
// 每个 row 独立算 lo/hi/scale
for (int col = 0; col < 128; ++col) { lo = min(lo, x); hi = max(hi, x); }
const float scale = max((hi - lo) / qmax, 1e-10f);
...
scale_axis[row] = best_row[row] * scale;   // 行 × 该行的 scale
zp_axis[row]    = best_row[row] * lo;      // 行 × 该行的 zero point
other_axis[row] = best_col[row];           // ← 列因子存在这里
```

`record_bytes = rows*cols*bits/8 + (2*rows + cols)*2` 中那个 `+cols` 就是**列因子**。这与你档案 §3 问题 2 的推断一致。

### 3. 线程配置固定 128（4 warps）

`threadIdx.x` 直接当 col/row 索引（0..127），reduce 走 warp shuffle + 4-warp 汇总。不要另设 block 尺寸。

### 4. V 侧更敏感：K4V2 判死、K4V4 打平（阶段 0 实测）

- 只压 **K** 4-bit：语料 A **−0.179%** / B **+0.006%**（K 逐向量 cos 0.997055，高于生产 0.995566）⇒ **基本免费**。
- 只压 **V** 2-bit：A **+2.269%** / B **+2.499%** ⇒ **全部代价都在 V 的 2-bit 上**。

⇒ K4V2_g128 = **+2.551%(A) / +2.907%(B)**，超判据（≤ rk4v4 + 0.1%）**25–29 倍 ⇒ 判死**；且与旧 G64 上游同值（8.1180 / +2.553%）⇒ **是位宽问题，不是实现问题**。
K4V4_g128 = **−0.090%(A) / +0.224%(B)**，跨语料均值 +0.067% ⇒ **与生产 `rk4v4` 打平**。

⇒ **主档定 K4V4，K4V2 降为对照臂**（详见 `07` §7.1/§7.3）。

## 三、字节账（D=256，G128，per KV head；**record 口径**，ninfer P1 落地口径见「三·五」）

完整 36 组合，按 arena 真口径（`make_record_layout × head_slices`）计算，每格 = 下表旧值 + 6 B/token：

| K\V | 2 | 3 | 4 | 5 | 6 | 8 |
|---:|---:|---:|---:|---:|---:|---:|
| **2** | 152 | 184 | **216** | 248 | 280 | 344 |
| **3** | 184 | **216** | 248 | 280 | 312 | 376 |
| **4** | **216** | 248 | **280** | 312 | 344 | 408 |
| **5** | 248 | 280 | 312 | 344 | 376 | 440 |
| **6** | 280 | 312 | 344 | 376 | 408 | 472 |
| **8** | 344 | 376 | 408 | 440 | 472 | 536 |

（粗体：**280** = 主档 K4V4，且 = 生产 `rk4v4` 的 280；**216** = K4V2/K3V3/K2V4 同字节组，其中 K4V2 已判死 → 见 `07` §7.1/§7.3）

**K4V2_g128 = 216 B/token**，对生产 `rk4v4`（280）省 **22.9%**。327,680 context、4 个 KV head 下：**270.0 MiB vs 350.0 MiB，省 80.0 MiB**。

G64 对照：doc 的 222 是 ①make_layout 值；真实旧引擎 G64 实测 K4V2 = 228 / K4V4 = 292。**G128 每档省 12 B/token（228→216）仍成立。**

## 三·五、落地口径与已定路线（2026-10-13 用户已定）

**两套数字都要列清——上面那张表是 record 口径，不是 ninfer 里 K4V4 的实际占用：**

| 口径 | 闭式 | K4V2 | K4V3 | K3V3 | K4V4 | 来源 / 用途 |
|---|---|---:|---:|---:|---:|---|
| **record 口径**（上游 arena；本包字节账） | `32·(Kb+Vb)+24` | **216** | 248 | 216 | **280**（= 生产 `rk4v4`） | `make_record_layout × head_slices`，上游 `GGML_ASSERT` 锁死 |
| **ninfer P1 落地口径**（页自足，页 = 64 token） | `32·(Kb+Vb)+36` | **228** | 260 | 228 | **292** | ninfer `leading_extent` 按 64-token 页自足记账 ⇒ **恒定比 record 多 12 B/token** |

- P1 多的 12 B/token 来源：**维轴条目**（K 的 scale+zp 各 2×128、V 的 other 2×128，共 768 个 half 条目）在 tile 的**两页各存一份**（`P1几何与偏移表-20261013.md` §6）。
- P1 leading 规则：`k_code = 32·kb`、`v_code = 32·vb`、`k_scale = 10`、`v_scale = 8`（后两者与位宽无关，由维度决定）。
- 容量（327,680 ctx × 4 KV head）：K4V4 **365.0 MiB**（P1）/ 350.0 MiB（record，= 生产）；K4V2 **285.0 MiB**（P1）/ 270.0 MiB（record）。

**已定路线（按此执行）：**

1. **先按 (A) `K4V4` + P1 页自足把路径跑通。** ninfer 里 K4V4 = **292 B/token**（不是 280），对生产 280 是 **+4.29%**；换来的是每页自足、**消费核不需要 sibling 页**，落地最简单。
2. **"与生产同字节（280）"只有走 blob 紧凑存储**（tile 一条 record 布局、不按 64-token 页自足，等价 record 口径）**才成立**——**属后续可选项**，本阶段不做。（相关备选：`P1几何与偏移表-20261013.md` §8-6 的 P2「维轴只存偶数页」= K4V2 222 B/token，需 sibling 寻址，同样未实现。）
3. **随后做全档位 36 组合**（K/V 独立 2/3/4/5/6/8-bit）：CLI 走 `--kvarn-k-bits / --kvarn-v-bits`；plane 的 leading **直接用 `P1几何与偏移表-20261013.md` 的 CSV 表**（`offsets-g128/out/offsets_p1_g128.csv`，36 档 × 4 平面），**不重新推**。全档位 P1 值 = 上面 record 矩阵每格 + 12。

| 阶段 | 内容 | 产出 |
|---|---|---|
| **0** | 误差归因实验（**已完成 2026-10-13**） | 只压 K 4bit 免费（语料 A −0.179% / B +0.006%，K 逐向量 cos 0.997055 高于生产 0.995566）；只压 V 2bit 是全部代价（+2.269% / +2.499%）⇒ K4V2_g128 = +2.551%(A)/+2.907%(B)，超判据（≤+0.1%）25–29 倍，与旧 G64 上游同值 ⇒ 位宽问题、非实现问题 |
